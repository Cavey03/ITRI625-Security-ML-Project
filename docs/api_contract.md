# API contract (v1.0)

The phishing classifier API sends and receives JSON over HTTP. The code version of this
contract is [`api/schemas.py`](../api/schemas.py). If this page and that file disagree,
the file is correct. [`tests/test_contract.py`](../tests/test_contract.py) checks that
every implementation (the mock now, the real API from Milestone 8) follows the contract.

- **Base URL (local):** `http://127.0.0.1:8000`
- **Interactive docs:** `http://127.0.0.1:8000/docs` (generated by FastAPI)
- **Labels:** `0 = legitimate`, `1 = phishing`, used everywhere in the project
- **Probability:** each endpoint returns `probability_phishing` in [0, 1]. `label` is
  `phishing` when `probability_phishing >= threshold`.

---

## `GET /health`

Checks whether the API is running and the model has loaded. The app should call this at
startup.

```json
{ "status": "ok", "model_loaded": true, "model_version": "distilbert-v1",
  "device": "cuda", "api_version": "1.0" }
```

`status` is one of `ok`, `loading` or `error`. Only send predictions when `model_loaded` is `true`.

---

## `POST /predict`

**Request**

```json
{ "subject": "Your account has been suspended",
  "body": "Dear customer, verify your details at http://secure-login.example.com",
  "threshold": 0.5 }
```

| field | type | required | notes |
|---|---|---|---|
| `body` | string | yes | Raw text or HTML. The server cleans it. Max 100 000 characters |
| `subject` | string | no (default `""`) | Max 100 000 characters |
| `threshold` | float in [0, 1] | no (default `0.5`) | Only changes `label`; the probability stays the same |

`subject` and `body` can't both be empty or whitespace.

**Response 200**

```json
{ "label": "phishing", "label_id": 1, "probability_phishing": 0.973,
  "threshold": 0.5, "model_version": "distilbert-v1" }
```

## `POST /explain`

Takes the same request as `/predict`, plus an optional `"method": "integrated_gradients"`.
It returns the prediction plus an importance score for each word.

**Response 200**

```json
{ "label": "phishing", "label_id": 1, "probability_phishing": 0.69,
  "threshold": 0.5, "model_version": "distilbert-v1",
  "method": "integrated_gradients",
  "subject": "Urgent",
  "body": "Please verify your account. Thanks",
  "truncated": false,
  "words": [
    { "field": "subject", "start": 0, "end": 6,  "word": "Urgent", "score": 0.9 },
    { "field": "body",    "start": 7, "end": 13, "word": "verify", "score": 1.0 },
    { "field": "body",    "start": 28, "end": 34, "word": "Thanks", "score": -0.6 }
  ] }
```

This example is shortened. A real response lists every word in the text that was scored.

The response carries its own `subject` and `body`, and the app must use these, not the user's input:

- They hold the **cleaned** text the model actually read. HTML is stripped and whitespace
  collapsed, so it can differ from what the user typed or loaded.
- `start` and `end` are character positions **in these cleaned strings**, with `end`
  exclusive. So `body[7:13] == "verify"`. The app shows the cleaned text in a read-only
  box and highlights `[start, end)`.
- `score` is in [-1, 1]. **Positive = pushes towards phishing (red)**, negative = pushes
  towards legitimate (green). The scores are scaled so the strongest word has |score| = 1.
  The number shows how strong a word is compared with the others in the same email; it is
  not a probability.
- `truncated: true` means the email was longer than the model reads (256 tokens). Words
  after that point get no score. Show a note in the app when this happens.

## `POST /predict_batch`

Upload a CSV file and get a prediction for each row.

**Request:** `multipart/form-data` with a field named `file`. Optional query parameter
`?threshold=0.5`.

The CSV needs a header row. It must have a `body` column; `subject` and `id` are optional.
Use UTF-8 and quote fields that contain commas. Limits: 5 MB and 1 000 rows.

```csv
id,subject,body
e1,Invoice overdue,"Please pay now at http://pay.example.com"
e2,Lunch?,"Are we still on for Friday?"
```

**Response 200**

```json
{ "n_rows": 2, "n_scored": 2, "threshold": 0.5, "model_version": "distilbert-v1",
  "results": [
    { "row": 0, "id": "e1", "label": "phishing", "label_id": 1,
      "probability_phishing": 0.91, "error": null },
    { "row": 1, "id": "e2", "label": "legitimate", "label_id": 0,
      "probability_phishing": 0.04, "error": null } ] }
```

If one row fails, for example because both fields are empty, the whole batch still
succeeds. That row gets `error` set and nulls for the prediction fields.

---

## Errors

Every error returns JSON with a `detail` field.

| status | when |
|---|---|
| 400 | CSV couldn't be parsed or has no `body` column |
| 413 | Batch file larger than 5 MB or longer than 1 000 rows |
| 422 | Request failed validation: missing `body`, both fields blank, text too long, threshold outside [0, 1] |
| 503 | Model not loaded yet (`/health` shows `status: "loading"`) |

If the server isn't running at all, the app gets a connection error, not an HTTP
status. The app has to handle that case too (see the app handover brief).

## Mock server

[`api/mock_app.py`](../api/mock_app.py) follows this contract, but its scores are **fake**.
They come from a keyword list, not a model. Use it to build the app now:

```bash
uvicorn api.mock_app:app --port 8000
```

When the real API is ready, run `uvicorn api.main:app --port 8000` instead. The app
shouldn't need any code changes.
